# fastforks-website

Project site for [fastforks](https://github.com/kleinicke/fastforks). Served by the Cloudflare Pages project
`fastforks` at https://fastforks.pages.dev and https://fastforks.dev (once the custom domain is added).

SvelteKit 3 + Svelte 5 + TypeScript on [Vite+](https://viteplus.dev) (Vite, Oxlint, Oxfmt, Vitest behind one `vp`
CLI), prerendered to static HTML (adapter-static), deployed on Cloudflare Pages.

## Commands

```bash
pnpm install
pnpm dev          # vp dev, http://localhost:5173
pnpm check        # vp check (format, lint, TS types) + svelte-check; must stay clean
pnpm fix          # vp check --fix: format and autofix
pnpm build        # vp build, static site in build/
pnpm sync         # refresh src/lib/data/models.json from the fastforks repo
```

## Data

All numbers come from `src/lib/data/models.json`, generated by `scripts/sync-data.ts`:

- `docs/overview.md` of the fastforks repo (`FASTFORKS_REPO`, default `../fastforks`): per-task inputs, picks
  and the model table (times, gain, peak memory, commercial flag).
- `uv run fastforks list --format json`: code and weights licences.
- `docs/data/devices.toml` + `docs/data/speed/<slug>.jsonl`: the survey devices (Apple M1 Pro, L4, L40S, A10, ...).
  Per model and mode the fastest passing row over all dtypes (`ok`, not a golden fail), else its status
  (unsupported, failed, OOM), the same rule as the generated device pages. Surveys time portable and kernels only,
  so their gain is kernels vs portable. A new device in `devices.toml` shows up after `pnpm sync`, no code change.

- `docs/` pages, rendered by `scripts/docs.ts` into `src/lib/data/docs/`: one `/models/<family>` page per family
  section of `docs/models/<task>.md`, `/tasks/<task>`, `/devices/<slug>`, and the guides in `PAGES` (`/usage`,
  `/benchmarks`, ...). Links between docs pages become site routes; only source files and the api/ stubs stay on
  GitHub. The family variant tables also give each model's per-backend peak memory (original, portable, kernels).

Never edit the JSON or type numbers into pages by hand. Regenerate the overview in the fastforks repo,
run `pnpm sync`, commit the JSON. The headline gains compare kernels with the authors' original code only.

## Notes

- Vite+ is a local dev dependency (`vite-plus`); run it through the scripts or `pnpm exec vp`, no global install
  needed. `vite` stays a dev dependency aliased to `@voidzero-dev/vite-plus-core`, and `pnpm-workspace.yaml`
  overrides every other `vite`/`vitest`. Without the direct alias pnpm installs a second, real Vite for SvelteKit's
  peer and `vp dev` fails with `vite_ssr_environment_not_runnable`. Bump `vite-plus`, the alias and the overrides
  together. pnpm's "unmet peer vite" warnings are expected (it compares against the Vite+ version number).
- `vp check` does not read `.svelte` files; `svelte-check` covers them. Format and lint settings live in the `fmt`
  and `lint` blocks of `vite.config.ts`.
- SvelteKit 3: config lives in `vite.config.ts` (`sveltekit({...})`, no `svelte.config.js`); `$lib` is gone,
  use the subpath import `#lib/...` with the file extension for `.ts` files (`#lib/site.ts`).
- `pnpm` needs the `packageManager` field here because a stray `~/package.json` declares yarn.
- Deploy: `pnpm ship` builds with `VITE_SITE_URL=https://fastforks.dev` (canonical and og URLs; without it they
  fall back to fastforks.f-kleinicke.de) and uploads `build/` with wrangler to the Pages project `fastforks`, branch
  `main`. No Git integration: Cloudflare does not build from the repo. Needs `wrangler login` (yours, once; again
  when the token expires). Headers, caching and `noindex` on `*.pages.dev` live in `static/_headers`.
- No external fonts, analytics or cookies; Impressum and Datenschutz link to f-kleinicke.de.
